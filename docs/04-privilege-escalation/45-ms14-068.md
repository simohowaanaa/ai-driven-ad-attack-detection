# 45 — MS14-068 (Kerberos PAC Forgery)

| Champ | Valeur |
|-------|--------|
| **Tactique MITRE** | Privilege Escalation |
| **Technique MITRE** | T1558 |
| **Phase kill chain** | Privilege Escalation |
| **CVE** | **CVE-2014-6324 (MS14-068)** |
| **Privilèges requis** | Un compte de domaine standard |
| **Impact** | Critique (utilisateur standard → Domain Admin) |

---

## 1. Description

Le **PAC** (Privilege Attribute Certificate) est la partie du ticket Kerberos qui décrit **les groupes et privilèges** de l'utilisateur. Le DC est censé le **signer** pour garantir qu'il n'est pas falsifié. **MS14-068** est un bug historique : le DC acceptait un PAC signé avec un algorithme faible (voire non-clé), permettant à un **utilisateur standard de forger un PAC** revendiquant l'appartenance à **Domain Admins**. Le DC le croyait → élévation immédiate. Bien que très ancien (2014), il reste un cas d'école et se rencontre encore sur des DC non patchés/legacy.

## 2. Prérequis
- Un compte de domaine standard (nom + mot de passe + SID).
- DC non patché (correctif de novembre 2014).

## 3. Procédure de simulation (lab)

```bash
# Forger un TGT avec un PAC "Domain Admin"
goldenPac.py datacorp.local/othmane:Marketing2025@dc01.datacorp.local
# (historiquement : ms14-068.py + kekeo/mimikatz pour injecter le ticket)
```

**Résultat :** accès Domain Admin depuis un compte lambda.

## 4. Télémétrie générée (logs)

| Source | Event ID | Signification |

| Security (DC) | 4768 | TGT demandé |
| Security (DC) | 4769 | TGS avec un PAC incohérent |

**Anomalie clé :** un compte standard obtient soudainement des privilèges d'administrateur (PAC revendiquant des groupes qu'il n'a pas).

## 5. Détection

### Règle Sigma
```yaml
title: MS14-068 - Forged PAC Privilege Escalation
status: experimental
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4672        # privilèges spéciaux
    condition: selection
level: medium
falsepositives:
    - Nécessite enrichissement PAC vs appartenance réelle
```

### Traduction SIEM
- **XSOAR :** playbook comparant les groupes revendiqués dans le PAC aux groupes réels du compte → alerte si écart (même logique que Diamond Ticket, fiche 20).

## 6. Contre-mesures / Hardening
- **Patcher** MS14-068 (2014) — indispensable.
- Détection par cohérence PAC / privilèges.

## 7. Features pour l'agent IA
- Compte non-privilégié obtenant des 4672 (privilèges spéciaux).
- Écart PAC (groupes revendiqués) vs appartenance AD réelle.
- Élévation sans changement d'appartenance de groupe traçable.
